# Verified course concepts and their design effects

The original lecture PDFs were located in the student's historical downloads and relevant complete pages were inspected. Page numbers below are PDF page indices, starting at 1. Full copyrighted course decks and private feedback screenshots are not included in the repository.

| Course source | Verified pages | Concept applied | Concrete A2 decision and check |
| --- | --- | --- | --- |
| Week 1 Lecture 03, Human-Centred Intelligent Interaction and the Shape of the Module | 3–4, 8 | Automation and human control are separate; visible consequences, correction and global controls | Ranking is automatic, but hiding sponsored placements is an effective user action; ordinary ranking remains independent. |
| Week 2 Lecture 04, Perception, Attention and Feedback | 18, 20 | Feedback identifies the consequence of an action; acknowledgement avoids uncertainty | Settings immediately recompute results and update visible state. No quantitative response-time result is claimed. |
| Week 2 Lecture 05, Memory, Mental Models and Cognitive Load | 15–18 | A runnable mental model; visible memory boundaries; explanation soundness, completeness and dosage | Show actual inputs, excluded purpose use, remaining campaign priority and available controls; distinguish stopping use from deleting data. Explanations are opened on demand. |
| Week 2 Lecture 06, Action, Error, Agency and Decision | 9, 13 | Slips versus mistakes; undo; visible cause and persistent user override | Undo restores accidental setting changes. Disabled personalisation stays disabled until the user changes it. This does not claim all errors are recoverable. |
| Week 3 Lecture 07, Conversational Interfaces | 4, 11–12 | Clarify, confirm, correct and decline | Ambiguous requests offer specific options; a corrected budget retains purpose; no match retains the price cap. No costly purchase action is implemented. |
| Week 4 Lecture 12, Tools, Connectors and the Boundary | 5, 13–14 | Proposals are not execution; report actual return values | Explanations use ranking result metadata and actual state. This adapts the reporting principle; it does not claim a live LLM/tool loop. |

The report cites these as University of Birmingham (2026a–f). Lab 4/5 are separately acknowledged as 2026g. Lecture concepts support design reasoning, while engine tests establish only the prototype's tested behavior. Human comprehension requires separate evaluation.
